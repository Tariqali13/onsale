# Deploying the demo on free tiers

Everything below uses free plans. No credit card is needed for Neon, Upstash, Vercel or
Netlify; check Render's current terms when you sign up.

| Piece | Service |
| --- | --- |
| Postgres | [Neon](https://neon.tech) |
| Redis | [Upstash](https://upstash.com) |
| API | [Render](https://render.com) web service (Docker) |
| Web | [Vercel](https://vercel.com) or [Netlify](https://netlify.com) |

## 1. Postgres on Neon

1. Create a project, then copy the **direct** connection string: turn *Connection
   pooling* off, so the host has no `-pooler`. It ends with `?sslmode=require`.
   Migrations take a session-level advisory lock, which a transaction-mode pooler
   can't hold across statements; a single small API instance doesn't need pooling.
2. Nothing else: the API runs its migrations and seeds the demo event on start.

## 2. Redis on Upstash

1. Create a Redis database in the region closest to your Render region.
2. Copy only the `rediss://default:…@….upstash.io:6379` URL. Upstash also shows a
   `redis-cli --tls -u …` command; paste just the URL, with `rediss://` (TLS).

## 3. API on Render

1. **New → Blueprint**, pick this repository. Render reads `render.yaml`.
2. Fill in the prompted values:
   - `DATABASE_URL`: the Neon URL
   - `REDIS_URL`: the Upstash URL
   - `CORS_ORIGIN`: your web URL from step 4 (you can come back and set it after)
3. Deploy, then open `https://<your-api>.onrender.com/health`. Expect
   `{"ok":true,"db":true,"redis":true}`. API docs are at `/docs`.

Free Render services sleep after a period without traffic, so the first request after a
while takes up to a minute. The web app shows a "waking up" message while that happens.

## 4. Web on Vercel (or Netlify)

1. Vercel: import the repository and set the **root directory** to `apps/web`.
   Netlify: import with no base directory; the root `netlify.toml` builds `apps/web`
   and sets `VITE_API_URL` (edit it if your API URL differs).
2. Framework preset: Vite. Build command `npm run build`, output `dist`.
3. Environment variable `VITE_API_URL=https://<your-api>.onrender.com`.
4. Deploy, then put the resulting URL into the API's `CORS_ORIGIN` and redeploy the API.

`apps/web/vercel.json` and the root `netlify.toml` already handle client-side routing.

## Staying inside the free limits

- The admitter and reconciler sleep after 60 seconds without buyer traffic, so an idle
  deployment makes no Redis calls.
- `RATE_LIMIT_STORE=memory` (set in `render.yaml`) avoids a Redis call per request.
- A "Release 2,000 buyers" run costs roughly 20–30k Redis commands. Upstash's free tier
  allows 500k a month, which is plenty for a portfolio demo.
- `ADMIN_TOKEN` is generated by Render. Use it to reset the demo at any time:
  `curl -X POST -H "Authorization: Bearer $ADMIN_TOKEN" https://<api>/events/<event-id>/reset`.
  Visitors can reset it themselves once it is 90% sold.

## Optional: Stripe test mode

Set `PAYMENT_PROVIDER=stripe` and `STRIPE_SECRET_KEY=sk_test_…`. The API refuses to start
with a live key.
